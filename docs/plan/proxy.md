# Plan: proxy/ (mitmproxy addon, xg_netpolicy, Unbound, nftables)

Sources: [audit/proxy.md](../audit/proxy.md) (I-PROXY-1..32), [features/proxy/](../features/proxy/README.md) (F64-F70).
Plan written 2026-11-17. Nothing run while planning.

Rules for every step: one component, <300 changed lines, one kind of change, test in the same step, then
`python3 -m pytest -q proxy/tests` and `ruff check proxy --select E,F,W --ignore E501,E731`.
**[APPROVAL]** = changes a documented feature; **[CROSS]** = another component's plan has the matching step.
Steps that touch `xephyguard.nft` or `unbound.conf` are "config-checked only" unless run with `nft -c -f` / `unbound-checkconf` (run them where available and say so).

## Phase 1: Critical/High security and bugs
- [x] Step 1: `server_connect` refuses loopback, link-local, CCC-own addresses and non-80/443 ports for every client (fixes I-PROXY-1; touches F64, F67, F68, F70)
  Done 2026-11-24. `server_connect` is now async and refuses, for every client (exempt too) and both listeners, ports other than 80/443 and loopback (incl. `localhost`, `*.localhost`, IPv4-mapped `::ffff:127.x`), link-local (169.254/16, fe80::/10), unspecified, multicast and `ccc_ip` destinations, via the new pure `proxy_logic.refused_destination`. A hostname (explicit listener) is resolved with the loop's `getaddrinfo`; any refused address refuses the connection, otherwise it is pinned to the checked address (SNI kept as the name), so a second lookup cannot rebind to loopback. Only `ccc_ip` counts as CCC-own; the WAN address is not known to the state. New tests: 11 destinations × test/exempt/no-group client refused, public 80/443 allowed, name pinning and a name resolving to 127.0.0.1 refused. F67 updated. 38 passed, ruff clean.

- [x] Step 5: Re-apply `sets.nft` on startup and on nftables reload even if file content is unchanged (fixes I-PROXY-5; touches F66)
  Done 2026-11-25. `generate --watch --apply` forces `nft -f sets.nft` on its first apply, so files left by `netpolicy-run.sh`'s pre-generation or from before a reboot are loaded even when unchanged. While the state digest stays the same it checks every `--resync` seconds (default 10) whether the live sets (`nft -j list table inet xephyguard`; prefixes, ranges and wrapped elements collapsed with `ipaddress`) still equal `sets.nft`; on a mismatch (xephyguard.nft reloaded, which deletes the table, or sets edited by hand) it re-applies and then flushes conntrack for every test/isolated PC. - [x] Step 6: Watch loop catches all expected exception types per iteration and keeps running; logs and counts failures (fixes I-PROXY-6; touches F64, F65, F66)
  Done 2026-11-25. `generate --watch` now catches every `Exception` per iteration (KeyboardInterrupt and the sleep stay outside). A document that won't parse or validate (`"groups": null`, a non-str `lan_if`/`network_mode`, bad JSON, not an object) becomes `InvalidState`: logged once, and that digest is skipped until the CCC writes a new one, so the previous files and applied sets stay. Any other error (OSError when the state is replaced mid-read or the out dir is unwritable, a tool that can't run, a bug) is logged with a traceback and the same digest is retried next iteration with every file treated as changed, so a file written before the failure is still applied. Failures are counted (total and in a row); a persistent one is logged on the 1st, 2nd, 4th, 8th... attempt, and "recovered after N" when it clears. Step 4's order is unchanged (`apply` flushes conntrack only after `nft -f` succeeded; a failed apply leaves `restricted` as it was, so the retry flushes again), and Step 5's first-pass apply and `--resync` check are kept; an error inside the check or its re-apply is caught the same way and retried at the next check. One-shot mode (no `--watch`) now exits 1 on a failure (`netpolicy-run.sh` already runs it with `|| true`). Left for ccc-deploy Step 25 (I-CCC-11): `netpolicy-run.sh` still only `wait`s on Unbound, so a watcher that dies anyway is not restarted; not a one-line change in POSIX sh (`wait -n` is not portable to dash). Not run: `nft -c -f` (no nft here, Docker and WSL unavailable; `xephyguard.nft` unchanged). F64, F65, F66 updated. 59 passed, ruff clean.

## Phase 3: Config and secrets, signatures in data/
- [x] Step 13: Write `proxy.json` mode 0600 (owner mitmproxy uid 1500), or move `events_token` to env (fixes I-PROXY-13; touches F70, F68) [CROSS: server Step 22]
  Done 2026-11-25, **env `XG_INTERNAL_TOKEN` chosen, not a 0600 file**. Why: the token then sits in no file the proxy reads, so no file mode can regress (a `cp`, a backup, `_write`'s chmod); the netpolicy container (root) needs no chown to the proxy image's uid 1500, so the two images are not coupled by a uid; it is the same secret from the same `.env` that the screen gateway already gets by env; `/proc/<pid>/environ` is readable only by uid 1500 and root, and `docker inspect` needs docker/root. `generate.proxy_json` no longer writes `events_token` (proxy.json stays 0644 and holds nothing secret). `EventShipper.token()` reads env `XG_INTERNAL_TOKEN`; only when that is unset does it fall back to `events_token` from an older proxy.json, with one warning (also when there is no token at all). Production `docker-compose.yml` passes `XG_INTERNAL_TOKEN: ${XG_INTERNAL_TOKEN}` to `proxy` (install.sh already generates it); `docker-compose.local.yml` already gives it via `env_file: .env.local`; `gosu` in `proxy-entrypoint.sh` keeps the env. CROSS server Step 22 (done as S-24, state.json 0640): server still to do, `NetworkPolicyWriter` can stop writing `events_token` into state.json, since netpolicy no longer forwards it (no server code touched here; the State field is kept so the current document still parses). New tests: proxy.json has no token, the shipper sends the env token (env wins over the file), the fallback with warning, compose passes the env to `proxy` (4 fail on the old code). F70, THREAT_MODEL row 31 updated. Not run: `nft -c -f` (not touched; no nft here), `docker compose config` (Docker unavailable). 82 passed, 2 skipped, ruff clean.
