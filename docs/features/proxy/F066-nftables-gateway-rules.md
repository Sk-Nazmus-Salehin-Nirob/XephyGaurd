# F66. nftables gateway rules

- **Component:** proxy
- **Area:** 12. Network enforcement (gateway, DNS, proxy)
- **Source:** [docs/FEATURES.md](../../FEATURES.md) (status legend, roles, `S/` = `server/app/`, `A/` = `agent/`)

- **What:** forwards lab traffic, redirects HTTP(S) to the proxy, blocks DoH/DoT IPs and QUIC, gives Test-mode PCs no forwarded egress, and drops VPN/tunnel ports (`vpn_ports` in `data/network/proxy.yaml`) for block_ai PCs only.
  VPN/tunnel ports: in `forward`, before `ct state established,related accept`, PCs in `block_ai_clients` are dropped towards the TCP ports in `vpn_tcp_ports` and the UDP ports in `vpn_udp_ports` (default: WireGuard 51820/udp, OpenVPN 1194/udp+tcp, IPsec 500/4500 udp, PPTP 1723/tcp, SSH 22/tcp, L2TP 1701/udp), so a tunnel opened before the PC joined block_ai stops at its next packet without a conntrack flush. The ports reach `sets.nft` through state.json `vpn_ports` (`"port/tcp"` or `"port/udp"`), which the CCC copies from the YAML (`NetworkSeed` signature, not a setting; server S-59, `server_shaped_document_with_vpn_ports`); a missing or unusable list uses the same values built into `xg_netpolicy/state.py` (`builtin_vpn_ports_equal_data_yaml`), a bad entry is skipped with a warning. Not covered: VPNs on 443/80 (they go to the proxy like any HTTPS), other ports, GRE/ESP without NAT-T, IPv6. No rule reads `exempt_clients`: exempt PCs get the plain lab path, the set is filled only so `nft list` shows them. Groups are disjoint (exempt wins, [F64](F064-gateway-or-proxy-only-network-mode.md)), so a PC listed in both exempt and block_ai is only in `exempt_clients` and is no longer dropped towards VPN ports.
  On the WAN card the CCC accepts only replies to its own connections, ICMP, DHCP replies and SSH (22); the proxy listeners, Unbound, the dashboard and every other host port are lab-side only (`wan_input` chain).
  In `forward`, the drops for test and isolated PCs (both directions) come before `ct state established,related accept`, so a VPN/SSH tunnel opened before a Test session or isolation stops; `xg_netpolicy` also runs `conntrack -D -s <ip>` for PCs that newly joined those sets (all of them when the watcher starts).
  The watcher applies `sets.nft` on its first pass even if the file is unchanged, and every 10 s (`--resync`) compares the live sets (`nft -j list table inet xephyguard`, the two port sets included) with it; after a reboot or an nftables reload empties them, it re-applies `sets.nft` and then flushes conntrack for every test/isolated PC. A failing check or re-apply is logged and retried at the next check; the watcher keeps running.
  `doh_ips` are collapsed (`ipaddress.collapse_addresses`) before they go into `resolver_ips`/`resolver_ips6`, so overlapping or duplicate entries (`45.90.28.0/24` plus `45.90.28.1`) no longer make the interval set, and with it the whole atomic `nft -f`, fail (`sets_nft_collapses_overlapping_resolver_ips`). Every `nft -f sets.nft` result is written to `/var/lib/xephyguard/net/health.json`: `nft_ok` true/false (null with `nft_skipped` in proxy_only or without the table), `nft_error` (nft's message), `nft_failed_since` (start of the current run of failures), `nft_checked_at`; the error is still logged, conntrack is not flushed after a failure, and the `--resync` check retries it every 10 s because the live sets then differ (`apply_writes_nft_health_flag`, `conntrack_not_flushed_when_nft_fails`). Nothing reads the flag yet (server/ccc-deploy: show it on the dashboard or use it as the netpolicy healthcheck).
  A PC address that is not IPv4 in `lab_subnet` is left out of the sets with a warning; the other PCs' sets are still loaded (`generate_and_proxy_enforce_other_pcs_when_one_ip_is_bad`).
- **Code:** `proxy/nftables/xephyguard.nft`, `xg_netpolicy` (`apply_skips_nft_in_proxy_only_or_without_table`, `forward_restricted_drops_come_before_established`, `forward_drops_vpn_ports_for_block_ai_before_established`, `sets_nft_fills_vpn_port_sets`, `apply_flushes_conntrack_after_sets`, `watch_flushes_only_newly_restricted_ips`, `sets_out_of_sync_compares_live_elements`, `watch_applies_sets_on_start_even_if_files_unchanged`, `watch_reapplies_sets_when_live_table_differs`, `watch_survives_failing_resync_check_and_apply`, `nft_accepts_ruleset_with_generated_sets` runs `nft -c -f` on the ruleset plus generated sets where nft may run, skipped otherwise).
- **Status:** partly working (ruleset syntax checked in CI; never run on a real gateway).
- **Test:** 1. On the CCC: `sudo nft list ruleset | grep xephyguard`.
